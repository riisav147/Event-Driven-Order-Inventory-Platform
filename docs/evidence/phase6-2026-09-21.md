# Phase 6 verification — 21 September 2026

Verified locally on PostgreSQL 17.11 and a temporary Redis 7.2.6 server, both bound to loopback. Java 25.0.1 ran Maven with Java release 21 compilation. Temporary services were stopped after the run.

Selected Maven `verify` run: 15 tests, zero failures/errors/skips. This was not the full Docker/Testcontainers suite or a Java 21 runtime test.

- Six PostgreSQL tests: 40 concurrent same-key checkout attempts returned one identical response and created one order; replay preserved the original response after an order status change; failed checkout rolled back the key and allowed retry; mismatch and expiry rejected reuse; owner isolation prevented another user replaying a response; HTTP checkout required a key and replayed the exact JSON response.
- Real Redis cache test: product list and individual-product JSON round-trips; a second read avoided JDBC; two-minute TTL inspected; creation invalidated cached data; accelerated expiry caused a new JDBC read. JDBC was mocked for query counting in this cache test.
- Redis-unavailable test: database reads and product creation succeeded despite cache connection failures. JDBC was mocked.
- Existing domain, JWT, and context tests: seven passed.

Migration V7 adds saved response JSON without rewriting existing migration history. The tests applied all six existing migrations (versions 1, 2, 3, 5, 6, 7) to the disposable database.

Reproduction commands and behavioral limitations are documented in [Redis and idempotency](../redis-idempotency.md). Earlier inventory and PostgreSQL Testcontainers tests were not executed during this run. No throughput or latency improvement is claimed.
