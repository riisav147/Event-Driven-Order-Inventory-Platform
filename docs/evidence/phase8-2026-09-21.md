Kafka proofs:

- Complete a real simulated payment while the notification listener is stopped; order is CONFIRMED before any receipt, then listener restart consumes the event.
- Repeating payment does not invoke the publisher a second time.
- A rolled-back application event and a declined payment publish no confirmation.
- Six sequential records with one order key arrive in one partition and retain sequence.
- Restart from committed group offsets resumes without replaying a previously acknowledged record.
- Explicitly rewind a stopped test consumer group: the same event is delivered again and creates another receipt, demonstrating the deduplication gap rather than hiding it.
- Inject a consumer database outage: no receipt and no offset advance past the failed record; recovery retries successfully.
- Unit tests reject invalid key/version/payload, tolerate additive JSON fields, and exercise immediate/asynchronous producer failures without throwing into the committed workflow.
