## Failure/recovery evidence

- Business state and outbox are atomic: fault injection after outbox insertion rolls back payment finalization and the event row; same-intent payment retry recovers the already-recorded provider outcome.
- Crash-before-publication simulation: commit an order while relay scheduling is disabled; a fresh relay instance finds the pending intent and delivers it.
- Broker failure simulation: an exceptionally completed send future leaves the row pending, with attempt/error metadata and a future retry time; after advancing the retry time, the real broker receives it.
- Ack-before-mark simulation: send to Kafka, leave an expired publishing lease, then reclaim/send again. Notification remains single despite the duplicate.
- Multiple relays race over eight same-aggregate events: each is claimed once in the normal case and reaches the consumer in sequence. A stale worker cannot mark a successor's claim published; the network callback asserts no active DB transaction.
- Twenty-four concurrent duplicate consumer calls create one processed marker and one receipt. A failed receipt insertion rolls back its marker and a subsequent retry succeeds.
- Consumer restart resumes committed offsets. Explicit test offset replay advances again without creating additional receipts.
- Transient consumer failure retries and succeeds; persistent transient failure invokes the consumer four times (initial plus three retries) before DLT. Permanent failure invokes it once before DLT.
- Malformed JSON is durably inspected through DLT and refused by the replay validator. Valid failed events can be replayed through the admin HTTP endpoint; customer requests are forbidden, repeated admin requests return the same outbox ID, and actor/reason audit is preserved.
- Unit fault injection verifies a failed DLT send is not reported as successful recovery. This is a mocked failed send, not a physical broker-kill test.
- Scheduler wiring executes automatically, and each poll is capped at ten claims. Kafka-disabled payment tests still persist a pending outbox event.
- `bash -n scripts/messaging-status.sh` passed.

Test harness corrections: fault injection was moved from a mandatory-transaction publisher proxy to the actual JDBC write; fresh broker runs now use unique topic namespaces so Kafka coordinates cannot collide with retained DLT audit data from previous test runs.
