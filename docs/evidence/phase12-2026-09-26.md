## Live operational smoke

Native Prometheus 3.14.0 and Grafana 13.2.2 were started on loopback ports 59090 and 53000 with the repository's alert rules and dashboard. All three built application services were started on ports 58080/58082/58083 with native databases. Kafka was disabled for this dashboard-only smoke; real Kafka propagation and lag were verified in integration tests above.

`scripts/observability-smoke.rb` passed:

- 100 successful read-only catalog requests;
- provisioned 18-panel dashboard retrieved from Grafana;
- every panel's PromQL query accepted by Prometheus;
- nonempty live HTTP, JVM and Hikari pool metrics;
- Grafana's Prometheus data-source health check OK.

This verifies dashboard provisioning and queries through APIs, not a visual browser review of panel rendering. It does not claim nonempty payment/Kafka panels in the read-only native smoke.

All services had tracing export enabled and deliberately pointed at an unavailable endpoint. Exporter timeouts were observed, while all catalog requests succeeded. Structured JSON request logs included service name, trace ID, correlation ID, outcome and duration without the tested credentials. This is a bounded smoke check, not a comprehensive secret audit or load benchmark.

## Alert rules

Native `promtool check rules alerts.yml` accepted all six rules. `promtool test rules alerts.test.yml` passed controlled firing/recovery scenarios for service unavailable, outbox age, stuck saga, growing consumer lag, pending dead letters and blind telemetry. These are deterministic signal tests, not a claim that external notifications were delivered. No external alert receiver is configured.
