## Evidence

- Transient HTTP failure retries identical key/body once, then succeeds.
- Decline, ordinary 4xx and malformed success are not blindly retried; only explicit known business failure compensates inventory.
- Real slow-header and slow-body responses hit bounded deadlines. A tighter overall deadline truncates the second attempt rather than allocating a fresh full timeout.
- Refused TCP connection remains pending after bounded adapter attempts. This is not a blackholed-network/connect-timeout test.
- Circuit CLOSED → OPEN blocks network calls, timed recovery enters HALF_OPEN, two successful probes close it. Failed probes reopen it; failed half-open probes are not retried within the same logical call.
- A provider charge commits before a delayed response times out. HTTP payment returns 202/RESERVED, inventory stays reserved, and later same-intent reconciliation confirms one provider charge and one outbox event.
- An open circuit leaves the order RESERVED without contacting the provider. Recovery reconciles successfully.
- Customer requests to gateway metric endpoints receive 403; administrators can inspect call and circuit-state meters.

## Reproducible local burst

`HttpPaymentGatewayTest.concurrentSlowGatewayBurstDemonstratesResourceIsolation` sends 40 unrestricted requests to a loopback server that waits 700 ms before HTTP 503, then runs a simultaneous 40-caller protected burst against the same fault. The protected test uses 4 permits, a 200 ms attempt timeout, a 450 ms overall budget, and a four-attempt circuit sample (shorter than application defaults).

Final captured output:

```text
GATEWAY_BURST callers=40 baselinePeak=40 protectedPeak=4 protectedRequests=4 elapsedMs=226
```

At least 36 callers were immediately rejected by the concurrency limit; the admitted calls timed out and the circuit prevented further requests. All protected results were pending, not successful payments. This is evidence of fault containment and bounded request amplification, **not** a production throughput/latency benchmark. The test asserts broad bounds, not a fixed 226 ms expectation. Results vary with machine scheduling and environment.

## Limitations

This remains a simulated provider using the existing shared simulation ledger, not a real payment system or Phase 11 service/database extraction. The mock endpoint is unauthenticated and local-only. No real credentials or card data were sent. Caller timeout/cancellation cannot prove a provider charge was cancelled; UNKNOWN intents require same-key reconciliation.

The full repository Docker/Testcontainers suite, older Docker-only tests and Java 21 runtime remain unverified. No live Grafana dashboard, public deployment, automated order reconciliation worker or production resilience claim is included. Metric hooks and a settings/failure runbook are provided in [payment resilience](../payment-resilience.md).
